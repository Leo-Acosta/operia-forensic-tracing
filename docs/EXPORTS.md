# Exports

`operia/exports` is the canonical export service for OPERIA Forensic Tracing.

Supported canonical formats:

- JSON;
- CSV;
- Markdown;
- PDF;
- report JSON;
- report CSV;
- report Markdown;
- report PDF.

Forensic controls:

- every canonical export calculates SHA-256;
- every canonical export calculates MD5 for compatibility with legacy workflows;
- every canonical export creates a sidecar `.manifest.json`;
- every canonical export stores an `ExportManifest` database record;
- every canonical export writes an audit entry.

Professional report PDF controls:

- the public PDF renderer hides implementation details and internal engine messages;
- report authorship is shown as the analyst/operator, never as the platform itself;
- internal statuses are translated into professional case/report states;
- empty professional fields are omitted instead of rendered as blank rows;
- legal content is rendered once, prioritizing analyst-approved mappings and linked evidence;
- visible Spanish text is normalized for accents and `ñ`;
- PDF metadata and manifest information are separated from the narrative body.

Integrated final report for the Cybercrime Investigation Challenge 2026:

- the professional PDF keeps the executive cover, metrics, clean tables and case metadata;
- the report includes `Written Legal Evidence Report 2026` with sections A, B, C, D and `Final Investigative Summary`;
- section A documents tools, methodology, selection reason, tasks performed and limits;
- section B documents evidence identification, category, preservation, hash and custody;
- section C documents legal authority, investigative requests, legal basis, status and authorization documentation;
- section D connects evidence and findings with investigative relevance, legal significance, attribution limits and next steps;
- the rubric score is rendered only when a rubric evaluation exists for the case;
- media-authentication, blockchain and IoT sections are rendered only when the corresponding data exists;
- the public PDF must not expose raw JSON, internal model names, fallback states or implementation technology.

Manifest fields:

- product;
- export type;
- filename;
- file path;
- generated timestamp;
- generated by;
- organization id;
- user id;
- case id;
- report id;
- SHA-256;
- MD5;
- human review warning;
- chain-of-custody note.

Canonical routes:

- `POST /api/exports/json`
- `POST /api/exports/csv`
- `POST /api/exports/markdown`
- `POST /api/exports/pdf`
- `GET /api/exports/reports/{report_id}/{fmt}`
- `GET /api/exports/manifests`
- `GET /api/exports/manifests/{manifest_id}`
- `GET /api/exports/manifests/{manifest_id}/download`
